## Direction (options, not ranked against the above)

- **Profile / account-settings is entirely stubbed** — 7 `TODO: Implement API call` comments across `profile.tsx` and its 5 section components (personal, password, avatar, roles, 2FA). Backend already has the users table, password hashing, and token infra — personal-info + password-change are cheap to wire up; 2FA is genuinely new work.
- **Payment/door-locks/PMS integrations are UI-only** — forms `await sleep(800)` and toast success, no backend route exists for any of them. The `monitoring_logs` schema already models `'pms' | 'door lock' | 'payment'` log types, implying the backend contract was planned. Coarse effort, spike-first.
- **Guest-abc CRUD has no bulk import/export** — only single-entry create/update/delete; the seed script proves the bulk-write shape already exists internally. Worth a "copy entries from another property" spike before full CSV import.

## Dependency ordering

- **#5 (guest-abc tests) before #21 (property-scoping reconciliation) and #23 (pagination)** — characterization tests first, since both touch the same controller.
- **#1 (IDOR fix)** is trivial and independent — do it first regardless of what else gets picked.
- **#21 needs a product decision** (is cross-property reservation visibility intentional?) before any fix plan — flag as investigate, not build.
- **#9 (deploy drift) should be resolved before trusting #8's "it's fine, NODE_ENV=production" reasoning** — the real prod config can't be verified from this repo alone.
